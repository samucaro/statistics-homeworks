Exercise 1

Riemann and Lebesgue integration

Numerical integrals by partitioning the domain (Riemann) and by partitioning the range and measuring preimages (Lebesgue).

1. Two ways to slice an area

Why two definitions? Riemann's integral (1854) is built on the domain, and works well for functions that do not jump around too much. Lebesgue's (1902) is built on the range: it groups points by value. Lebesgue explained the difference with paying a debt: one can count coins in the order they come out of the pocket (Riemann), or first sort them by denomination and count how many there are of each (Lebesgue). The second way only needs to know how much of the domain takes each value — a measure — and does not care where those points are.

Riemann — partition the domain a = x₀ < x₁ < … < x_N = b, pick tags ξₖ ∈ [xₖ₋₁, xₖ]
∫ₐᵇ f = lim Σₖ f(ξₖ)·(xₖ − xₖ₋₁) as the mesh → 0, the same limit for every choice of tags
Darboux: L(P) = Σ inf f·Δxₖ ≤ ∫ ≤ U(P) = Σ sup f·Δxₖ; f is Riemann integrable iff inf_P U(P) = sup_P L(P)
Lebesgue — partition the range 0 = t₀ < t₁ < … < t_M, measure the preimages Eⱼ = {x : tⱼ ≤ f(x) < tⱼ₊₁}
∫ f dμ = lim Σⱼ tⱼ·μ(Eⱼ) = ∫₀^∞ μ({x : f(x) > t}) dt ("layer-cake" formula, for f ≥ 0)

How they relate. Two classical theorems answer the question “do they give the same value?”:

  • If f is Riemann integrable on [a, b], it is Lebesgue integrable and the two integrals are equal.
  • Lebesgue's criterion: a bounded f is Riemann integrable if and only if the set of its discontinuities has measure zero. So step functions (one jump) and Thomae's function (jumps at every rational, a countable set) are Riemann integrable; Dirichlet's function (discontinuous everywhere) is not.
  • For unbounded functions like 1/√x the proper Riemann integral does not exist; the improper Riemann integral (a limit) and the Lebesgue integral both exist and agree, because the convergence is absolute.

6. Pathological functions required

6.1 Dirichlet's function: the two approaches disagree

D(x) = 1 if x is rational, 0 otherwise. Every subinterval, however small, contains both rationals and irrationals, so for every partition L(P) = 0 and U(P) = 1: the Darboux sums never meet and D is not Riemann integrable. Concretely, Riemann sums depend on the tags: with the rational tags k/N they are all 1, with the irrational tags k/N + 1/(√2·N) they are all 0.

Lebesgue only needs the measure of the two preimages. {D = 1} = ℚ ∩ [0, 1] is countable, r₁, r₂, …: cover rₖ with an interval of length ε/2ᵏ, and the whole set is covered by total length ε, for every ε > 0. So μ(ℚ ∩ [0, 1]) = 0 and

∫ D dμ = 1·μ(ℚ ∩ [0,1]) + 0·μ([0,1] \ ℚ) = 1·0 + 0·1 = 0

Statistically: a uniform random point is irrational with probability 1, so E[D(U)] = 0 and Monte Carlo, in exact arithmetic, returns 0.

6.2 Thomae's function: the two approaches agree

T(p/q) = 1/q in lowest terms, T(x) = 0 for irrational x. It is discontinuous at every rational but continuous at every irrational. The discontinuities form a countable set (measure 0), so by Lebesgue's criterion T is Riemann integrable. The lower sums are 0; the upper sum on [k/N, (k+1)/N] uses the fraction with the smallest denominator in that interval, which I compute exactly with the Stern–Brocot / continued-fraction algorithm. For Lebesgue, {T ≥ 1/q} is a finite set of fractions for every q, so every level set has measure 0 and the integral is 0. Both approaches give 0, as the theorem predicts — but the Riemann sums get there slowly.

Thomae: upper Darboux sums and Riemann sums tend to the integral 0

6.3 The floating-point trap extension

A computer cannot sample Dirichlet's function: every floating-point number is a rational (an integer divided by a power of 2). A naive program that tests “is x rational?” on doubles answers yes for every input, so a Monte Carlo estimate returns 1 instead of 0, and no refinement fixes it. Even √2 and π are stored as rationals:

For these functions the computation has to be done by reasoning about the sets (countable ⇒ measure zero; smallest denominators), as above, not by sampling. This is why the tables in §6 come from exact rational arithmetic and symbolic tags, not from evaluating floating-point numbers.

  • Accuracy and convergence. For smooth functions the Riemann midpoint rule wins: order 2 at one evaluation per strip. The Lebesgue sum with exact level sets also converges, but its integrand μ({f > t}) can be less regular than f (for sin x it has an infinite derivative at the maximum, which costs half an order).
  • Efficiency. Lebesgue sums need the measure of each preimage. In one dimension that means solving f(x) = t (bisection) for every level and every monotone piece, ≈ 60 times the cost of a Riemann strip. Without that knowledge, the only way to measure the preimages is to sample the domain — and counting grid points is just a Riemann sum with the values rounded to the levels, so it is less accurate (an extra quantisation error ∝ 1/M).
  • Where Lebesgue's idea pays off numerically: Monte Carlo. Estimating measures with random points gives an error σ/√K that does not depend on smoothness or on the dimension of the domain. In one dimension it is far slower than Riemann (order ½), but in high dimension it is the method of choice — a direct use of statistics in numerical analysis. For 1/√x it is especially slow because Var(f(U)) = ∫ 1/x − 4 = ∞: the CLT error estimate does not even apply.
  • Where the two definitions really differ is not numerical but conceptual: Lebesgue's integral exists for functions (Dirichlet) and limits of functions where Riemann's breaks down, which is why probability theory is built on it — an expectation E[X] = ∫ X dP is a Lebesgue integral over an abstract sample space that has no “intervals” to partition.

Numerical computation of the normal CDF

An efficient and accurate method for Φ, compared with a trusted reference; why Φ has no elementary formula; erf and the numerical approaches.

8. The standard normal CDF

Following Hogg, McKean & Craig (§3.4), Z ~ N(0, 1) has density φ(z) = e^{−z²/2}/√(2π) and CDF

Φ(z) = P(Z ≤ z) = ∫_{−∞}^{z} (1/√(2π)) e^{−t²/2} dt, Φ(−z) = 1 − Φ(z), X ~ N(μ, σ²) ⇒ P(X ≤ x) = Φ((x − μ)/σ)

The book gives Φ only as a table (Appendix D, Table II): there is no formula of the familiar kind. The next two sections explain why, and what we do instead.

9. Why Φ is not an elementary function: Liouville's theorem required

Elementary functions are those obtained from rational functions by finitely many arithmetic operations, compositions, exponentials, logarithms and algebraic roots (trigonometric functions included, as complex exponentials). Differentiating an elementary function always gives an elementary function; the converse fails, and Liouville (1835) found the precise criterion for a large class of integrals:

Theorem (Liouville). Let f, g be rational functions, g not constant. Then ∫ f(x)·e^{g(x)} dx is elementary if and only if there is a rational function R such that f = R′ + g′·R. In that case ∫ f e^g dx = R·e^g.

For φ we have f = 1 and g = −x²/2, g′ = −x. An elementary antiderivative would need a rational R with

R′(x) − x·R(x) = 1
  • R has no poles. If R had a pole of order k ≥ 1 at some c, then R′ would have a pole of order k + 1 there, while x·R has order at most k: nothing could cancel it, so the left side would have a pole, but the right side is the constant 1.
  • So R is a polynomial, of some degree d. Then x·R has degree d + 1 and R′ degree d − 1, so R′ − xR has degree d + 1 ≥ 1 — it cannot equal the constant 1. (R = 0 gives 0 = 1.)

No such R exists, hence ∫ e^{−x²/2} dx is not elementary, and neither is Φ. This is not a lack of cleverness: the theorem proves that no finite combination of the usual functions will ever work.

10. The error function: an exact representation that still needs numerics required

When an important integral cannot be expressed with existing functions, mathematics gives it a name and studies it. The error function is

erf(x) = (2/√π) ∫₀ˣ e^{−t²} dt, erfc(x) = 1 − erf(x), Φ(x) = ½·[1 + erf(x/√2)], 1 − Φ(x) = ½·erfc(x/√2)

This representation is exact: erf is a fully characterised function — odd, entire (its Taylor series converges everywhere), solution of y″ + 2x·y′ = 0, with known asymptotic expansions and continued fractions. Every property of Φ follows from those of erf.

It does not remove the need for numerical methods, because naming a function is not the same as computing it. To get digits one still needs an algorithm — a series, a continued fraction, a rational approximation — with an error bound and a cost. This is not special to erf: exp, sin or log are also computed by libraries with polynomial and rational approximations; they only feel “closed form” because the work is hidden in the language. JavaScript, in fact, has no built-in erf (Python's math.erf and C's erf exist in the C library), so here every method is implemented from scratch.

13. Discussion required

  • Accuracy. The hybrid method stays near the limit of double precision (relative error ≈ 10⁻¹⁵) on the whole line, including Φ(−8) ≈ 6.2·10⁻¹⁶. Simpson with n = 100 is excellent near the centre but, like every method that computes a tail as ½ − (something close to ½), it loses all relative accuracy in the lower tail. The alternating Taylor series fails outright in the lower tail (x ≲ −6), and for |x| ≳ 8 even Φ itself is wrong: its terms grow to ≈ 10⁶ at |x| = 6 and ≈ 10¹² at |x| = 8 before cancelling to a result of order 1, so the rounding error (≈ 10⁻¹⁶ × the largest term) swamps the tail probability.
  • Convergence. Trapezoid and Simpson show the expected slopes −2 and −4. The series and the continued fraction converge geometrically, but at rates that depend on x in opposite ways, which is exactly why combining them works.
  • Efficiency. Fixed-cost approximations (A&S) are fastest but stop at ≈ 10⁻⁷ absolute error. The hybrid method costs a few times more and is accurate to 15 digits; the quadrature rules are both slower and less accurate. Production libraries (e.g. W. J. Cody's rational Chebyshev approximations, on which R's pnorm is based) reach the same accuracy as the hybrid at fixed cost, by fitting rational functions on a few sub-intervals.
  • Why tails matter in security. Statistical tests used in security compute p-values in the far tail. The NIST SP 800-22 randomness test suite, for instance, computes the p-values of several tests with erfc, and an anomaly detector with a 5σ threshold relies on 1 − Φ(5) ≈ 2.9·10⁻⁷. The fixed A&S formulas give that value with ≈ 0.2% relative error — fine — but their relative error grows further out, and computing a tail as ½(1 − erf) collapses to exactly 0 beyond ≈ 8.5σ (A&S 7.1.26 in the accuracy chart, the formula used in HW3 for KS distances, where it was adequate). A p-value of 0 declares an observation impossible. Tail probabilities must be computed directly, with small relative error, as the continued fraction does.

Conclusions

  1. For Riemann-integrable functions the Riemann and Lebesgue approaches converge to the same value, as the theory guarantees; numerically the Riemann midpoint rule is the more accurate and the far cheaper one in one dimension.
  2. Lebesgue's approach needs the measure of preimages: exact level sets are expensive, grid counting is a disguised Riemann sum, and random sampling (Monte Carlo) is the form in which the idea is useful in practice.
  3. The two definitions really part ways on functions like Dirichlet's: no Riemann integral, Lebesgue integral 0 — a result that only reasoning about measure, not floating-point sampling, can reach.
  4. Φ has no elementary formula (Liouville); erf gives it an exact name, and a numerical algorithm gives it digits. A hybrid of a positive-term series and a tail continued fraction reaches double precision everywhere, including the tails that statistical decisions depend on.
