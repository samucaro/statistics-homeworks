Interpretation of the assignment. The previous homeworks implemented the map private key → public key (Q = d·G, HW1) and its role in wallets (HW2), but not an encryption scheme. Here I build on that code the textbook EC-ElGamal encryption on the real secp256k1 curve, and — as the assignment states — restrict only the receiver's private key d to a small range [1, 2b) (b selectable, default 20 bits) so that attacks finish in seconds. Everything else uses full-size values.
Educational code: deliberately weak keys, no authentication, not constant-time. Do not use it to protect real data.

1. Toy public-key encryption on secp256k1 required

1.1 The algorithm, step by step

StepWhoComputationMeaning
1. Key generationBobd ←$ [1, 2b) ; Q = d·Gd private (here deliberately small), Q published. On real ECC d ∈ [1, n−1], n ≈ 2256.
2. EncodingAlicebytes → M ∈ E(Fp)Each ≤ 29-byte block becomes a curve point (Koblitz's method: x = 256·m + j, first j giving a valid point). Not encryption: anyone can decode with x ≫ 8.
3. EncryptionAlicer ←$ [1, n−1] ; R = r·G ; S = r·Q ; C = M + SFresh random r per block; the mask S hides M; Alice sends (R, C).
4. DecryptionBobS = d·R ; M = C − S ; decode MBob rebuilds the same mask from R and his private key.

Why decryption works: d·R = d·(r·G) = r·(d·G) = r·Q = S, because scalar multiplication commutes (it is repeated addition in an abelian group) — the same identity behind the Diffie–Hellman key exchange. Why it is (normally) secure: Eve sees G, Q = d·G, R = r·G and C. Computing S = dr·G from d·G and r·G is the Computational Diffie–Hellman problem; recovering d from Q is the ECDLP of HW1. With full-size keys both are believed infeasible on secp256k1.

2. The Caesar cipher required

Letters are numbers A = 0, …, Z = 25. With key k ∈ {0, …, 25}:

Encryption:  c = (p + k) mod 26        Decryption:  p = (c − k) mod 26

Suetonius reports that Julius Caesar used k = 3. Case is kept; spaces, digits and punctuation are copied unchanged (a common convention).

3. Similarities and differences required

The common idea. Both schemes encrypt by adding a key-dependent mask in a group and decrypt by subtracting it: Caesar adds k in the group Z26, EC-ElGamal adds the point S in the group E(Fp). Everything else differs — above all how often the mask is reused and who can compute it.

The index of coincidence IC = Σ nᵢ(nᵢ−1)/(N(N−1)) — the probability that two random letters of the text coincide — is ≈ 0.066 for English and is exactly unchanged by Caesar, because a permutation of the alphabet does not change the multiset of counts. That invariance is the statistical leak §4 exploits. The EC ciphertext bytes instead pass the χ² uniformity test and have IC ≈ 1/256: they carry no usable frequency information. Uniformity is not proof of security (HW1 §6), but non-uniformity like Caesar's is proof of insecurity.

4. Statistical cryptanalysis of the Caesar cipher required

4.1 The known language: corpus and model

Training corpus: ≈ 300,000 letters of public-domain English (Austen, Persuasion; Chesterton, The Man Who Was Thursday; Melville, Moby Dick), from Project Gutenberg via the NLTK corpus. Test texts are never used for training: Carroll, Alice's Adventures in Wonderland (main test) and Shakespeare, Julius Caesar in its 1599 spelling (an atypical text). Files: train · test · Shakespeare.

How many letters should be needed? Shannon's unicity distance U = H(K)/D is the ciphertext length beyond which, on average, only one key yields meaningful text. H(K) = log₂26 is the key entropy and D the redundancy of the language per letter. The more structure a model captures (letters → pairs → triples), the lower the entropy, the higher the redundancy and the fewer letters are needed:

4.2 The algorithm

input: ciphertext c, letter probabilities p₀…p₂₅ estimated from the corpus
for s in 0 … 25:                          # exhaustive search over the key space
    Oᵢ(s) = number of letters i in D_s(c)  = count of ciphertext letter (i + s) mod 26
    χ²(s) = Σᵢ (Oᵢ(s) − L·pᵢ)² / (L·pᵢ)    # L = number of letters
return the s with the smallest χ²(s)

Why it works. With the right key the candidate is English, so Oᵢ/L → pᵢ (law of large numbers) and χ² stays around its degrees of freedom (≈ 25) whatever the length. With a key wrong by t the candidate follows the rotated distribution pi+t, and the expected χ² grows like 25 + L·Δt, with Δt = Σᵢ (pi+t − pᵢ)²/pᵢ (Δmin is shown above). The signal grows linearly with L, the noise only like √L: longer ciphertexts make the attack easier, the opposite of what a cipher should do.

Caveat. The χ² test needs every expected count L·pᵢ ≥ 5, i.e. L ≳ 11,000 letters because of “z” — never satisfied here. We use χ² as a distance score, not as a hypothesis test. With few letters, one rare letter dominates the sum (a single “z” in 10 letters adds ≈ 220), which is why likelihood-based scores below do better on short texts.

Alternative scores optional, all plugged into the same 26-key loop:

  • Most frequent letter = E: no loop needed, but uses one number out of 26.
  • Unigram log-likelihood ℓ(s) = Σₜ log p(xₜ): maximum likelihood, equivalent to minimum cross-entropy with the corpus model.
  • Bigram / trigram log-likelihood: ℓ(s) = log p(x₁) + Σ log p(xₜ | xₜ₋₁) [ + … ] — a Markov model of the language, add-one smoothing for unseen n-grams.
  • Dictionary: fraction of letters in words found in the corpus vocabulary (uses the word boundaries that Caesar leaves visible).

Table of success rates

Reading the results.

  • Every frequency-based method reaches ≈ 100% within a few tens of letters; the point where each method reaches ≈ 80% matches its unicity distance in §4.1 (≈ 9 letters for unigram scores, ≈ 3–4 for trigrams). Shannon's theory predicts the experiment quite well.
  • Exploiting more structure helps most when text is short: trigram ≥ bigram ≥ dictionary ≥ unigram ≈ χ² ≫ “E” heuristic.
  • The “E” heuristic stays poor even at 100 letters: p(e) ≈ 12.5% vs p(t) ≈ 9% and p(a) ≈ 8%, and with L = 100 the counts are ≈ 12.5 ± 3.3 vs 9 ± 2.9, so the most frequent letter is often not E. Using all 26 frequencies at once is what makes χ² and likelihood scores robust.
  • The Shakespeare text (old spelling, verse, character names) is attacked almost as well: success is somewhat lower on very short excerpts, because its spelling and names are less predictable for a model trained on later prose, but it reaches ≈ 100% from about 15 letters. Caesar only needs the right shift among 26, and the overall shape of the letter distribution is stable across styles.

4.6 Limitations

  • Short texts. Below the unicity distance several keys give plausible text: e.g. CHEER shifted by 7 is JOLLY — both valid words, so no statistical method can decide.
  • Atypical texts. A text that avoids frequent letters breaks frequency assumptions. Demo — a lipogram without the letter E:
  • Wrong language model. The scores assume the plaintext language is known: an Italian ciphertext should be scored with an Italian corpus (different frequencies, e.g. more A, I, O). With the wrong model short texts fail more often.
  • Assumptions on the cipher. The attack knows the cipher is Caesar. For a general substitution (26! ≈ 288 keys) exhaustive search is impossible and statistics must guide a heuristic search; for Vigenère the index of coincidence first reveals the key length.
  • Non-text plaintexts (numbers, compressed data) have no linguistic redundancy and cannot be attacked this way — but the key space of 26 still falls to exhaustive search if any criterion recognises the right plaintext.

5. Breaking the toy ECC scheme through its restricted key space required

5.1 Attack design

Threat model. Eve knows the curve, G, Bob's public key Q, the range bound 2b, and intercepts (R, C). The key observation is that Q itself is an exact test for any guess of d: the guess is right if and only if guess·G = Q. No ciphertext and no statistics are needed to find d.

Brute force — O(K) time, O(1) memory

R ← O
for k = 1 … K−1:
    R ← R + G          # R = k·G, one addition
    if R = Q: return k

With d uniform in [1, K), the number of steps is uniform too: expected K/2.

Baby-step giant-step — O(√K) time and memory

m ← ⌈√K⌉ ;  write d = i·m + j
baby:  T[j·G] = j   for j = 0 … m−1
giant: Γ ← Q
for i = 0 … m:
    if Γ in T: return i·m + T[Γ]
    Γ ← Γ − m·G

If Q − i·m·G = j·G then Q = (i·m + j)·G. A time–memory trade-off (Shanks).

Decrypting “otherwise”? The other secrets are not weak: r is full-size (recovering it from R is a 256-bit ECDLP) and computing S from Q and R is the Diffie–Hellman problem. In this scheme the restricted d is the only door, and once it is open Eve decrypts exactly like Bob.

In both cases the attack is, at its core, an exhaustive search. Caesar fails because its key space is tiny and its ciphertext keeps the statistics of the plaintext; the toy ECC scheme hides the plaintext statistics perfectly and fails only because of the artificially small key space.

5.5 Why the same approach fails against properly configured ECC

  • Key space. With d uniform in [1, n−1], n ≈ 2256, brute force needs ≈ 2255 additions on average (last row of the table).
  • The best generic attacks only reach the square root. BSGS would need ≈ 2128 stored points — more memory than exists. Pollard's rho needs no memory but still ≈ √(πn/4) ≈ 2127.8 additions. Shoup (1997) proved that any generic algorithm needs on the order of √n group operations, so this is a lower bound for attacks that only use the group law.
  • No known shortcut for secp256k1. Its group order is prime (Pohlig–Hellman cannot split the problem), the curve is not anomalous (Smart's attack; see the p = 547 example in HW1), and its embedding degree is huge (pairing-based MOV/FR reductions do not apply). Its special endomorphism gives only a small constant speed-up.
  • Scale of public records. The largest ECDLP publicly solved on a prime-field curve is 112 bits (2009, a cluster of more than 200 PlayStation 3 consoles). For rho, 256 bits is 272 times more work.
  • “Not necessarily” feasible — but other doors exist. Full-size keys stop key search, not every attack: bad randomness for d or r (biased ECDSA nonces, HW1 §7.3), side channels in non-constant-time code, missing point validation (invalid-curve attacks), protocol flaws (§6), and, in the future, Shor's algorithm on a large quantum computer.

6.1 Demo: when the toy scheme becomes a substitution cipher

Naive variant: one point per character and one ephemeral key r for the whole message, so every character gets the same mask S — exactly like Caesar reuses k. The private key is a full 256-bit key: the attacks below never touch it.

The same lesson as Caesar: a cipher that maps equal plaintext symbols to equal ciphertext symbols leaks the frequency distribution of the language, whatever the size of its key. Here the key size is enormous and yet ≈ half of the text is readable from frequencies alone.

7. Conclusions

  1. Same skeleton, different security. Caesar and EC-ElGamal both add a mask in a group. Caesar reuses one mask from a set of 26; EC-ElGamal derives a fresh, unpredictable mask for every block from a public key.
  2. Statistics break Caesar. The ciphertext keeps the language's distribution (identical index of coincidence), so a corpus-based score recognises the key from ≈ 5–12 letters, as Shannon's unicity distance predicts.
  3. Key space breaks the toy ECC. Its ciphertext shows no usable statistics, but the restricted d can be found from Q alone, exactly and without statistics, in O(2b/2) with baby-step giant-step.
  4. Full-size keys move the attack out of reach. ≈ 2128 operations for the best generic attack, with a matching lower bound. What remains are failures of randomness, implementation and design — which is why §6 matters as much as key length.
